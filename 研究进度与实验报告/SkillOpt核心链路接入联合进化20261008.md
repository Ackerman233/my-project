## 具体实现

入口：[skillopt_core.py](../experiments/alfworld/joint_evolution/skillopt_core.py)。
框架与运行方式：[README](../experiments/alfworld/joint_evolution/README.md)。

| 阶段 | 实际调用 | 在本方法中的作用 |
| --- | --- | --- |
| 失败 Reflect | `skillopt.gradient.reflect.run_error_analyst_minibatch` | 读取失败训练轨迹，提出纠错、interrupt/恢复策略编辑 |
| 成功 Reflect | `run_success_analyst_minibatch` | 从成功训练轨迹提取可复用技能修改 |
| Aggregate | `skillopt.gradient.aggregate.merge_patches` | 失败优先地合并两组补丁，保留证据引用 |
| Rank | `skillopt.optimizer.clip.rank_and_select` | 从编辑池选择最多4项互补编辑 |
| Apply | `skillopt.optimizer.skill.apply_patch_with_report` | 应用真正被选中的编辑，保存逐项应用报告 |

技能文本和 interrupt JSON 位于同一个优化文档中。策略 JSON 必须整体替换，不能
修改边界、添加未知参数或产生不合法值。Apply 后重新解析为 `InterruptPolicy`，
直接传入原有队列执行器；因此策略修改不只是提示中的建议。

训练数据只传入公开动作、观察、队列和实际截断等执行字段。官方 Reflect 可以看到
完整训练轨迹；旧的最多12步摘要继续作为预览。原始隐藏状态、答案、选择/确认/测试
轨迹不传入优化器。每条编辑必须引用当前阶段收到的训练证据 ID；最终应用日志记录
策略修改引用了哪些失败证据。引用表明提出修改的依据，不等于反事实因果证明。

新候选仍须同时改变技能与策略；不合法、无更新、重复、没有收益或确认集不通过的
候选均不替换当前版本。最终版本在测试前冻结，再运行初始、仅技能、仅策略、联合
四组消融。确认集参与接受决策，最终测试不参与选择。

## 请求、失败与冻结

每候选最多4次优化请求：失败反思、成功反思、聚合、排序。沿用上游行为：没有某类
轨迹时跳过该类反思；只有一个补丁组时聚合无需请求；编辑数量不超过4时排序无需请求。
这些情况分别记录函数执行和实际请求数，不虚报模型调用。

只替换上游模型传输层，不修改上游源码。执行、反思、聚合、排序都经同一预算账本。
上游请求参数里的 `retries=3` 不会传给实际 API；适配器执行0次隐式重试，并按本项目
输出 token 上限收费。上游若捕获 API 异常后返回备用编辑，适配器仍会重新抛出异常并
停止运行；非法 JSON、截断、错误引用和无效排序拒绝候选，不靠备用编辑继续接受。

正式配置协议升级为 `joint-skill-interrupt-live-v2`，请求上限计入每候选最多4次优化，
并冻结上游反思、聚合、排序、编辑源码及所读提示模板。旧v1批次必须重新准备，不能
在旧冻结配置下悄悄切换方法。临时替换的传输函数会在成功或失败后恢复。

## 验证与证据

完整离线回归 **261 passed、5 skipped**；相对前一版新增20项测试。
测试覆盖官方函数实际调用、失败证据产生策略修改、执行行为改变、确认集不通过保留
旧版、训练数据隔离、各阶段共享计费、API异常不能被上游吞掉、非法结果不能回退接受、
策略越界/部分修改/目标缺失/仅改策略拒绝、无补丁不强制更新，以及输出截断保护。

两轮离线演示的模型回复由脚本提供，但反思、聚合、排序、应用、队列执行与评估使用
真实代码路径。第一轮训练包含一条失败和一条成功轨迹，实际请求顺序为：

```text
失败 Reflect → 成功 Reflect → Aggregate（5项编辑）→ Rank（选4项）
             → Apply（invalid_patience: 1 → 2，并修改技能）
             → 选择集通过 → 本轮确认集通过 → 接受
第二轮成功 Reflect → 上游聚合/排序无需请求 → 无进一步收益 → 拒绝
```

构造环境中，初始版本丢弃有效导航队尾，在1次规划预算内失败；策略修改后保留导航并
成功。最终四组中初始/仅技能失败，仅策略/联合成功；真实队尾截断由1次变0次。
这是用于验证失败反馈到可执行策略的端到端链路，**不是模型学到有效中断规则或
ALFWorld性能提升的证据**，也不能用该耐心参数代替证伪与依赖判断。
