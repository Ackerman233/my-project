## 多动作来源与截断证据

新六题的18次多动作调用全部执行了多个 primitive，平均每次调用执行1.316步。17次调用选择人工参数化子技能，另有3次模型原生多 primitive 调用；这两个计数不等于互斥的多动作分类。模型未调用 `@scan`，主要通过 `@inspect` 合并导航与打开。程序展开不能称为模型学会自主 chunking，也不能由57调用与75步推算对单步基线的成功率或成本优势。

最终四题 dynamic 在一个未完成的 CD 灯下查看任务中真实丢弃了 `use desklamp on cd 1`。在新建真实环境中重放完整前缀，逐步核对公开动作列表、反馈和终止状态，随后执行该队尾，得到 `Nothing happens.`。这支持此次截断避免一条局部无效动作；原任务仍未完成，不能声称成功恢复。反事实审计没有模型调用。

新六题真实截断、发现中断均为0。虽然发现中断开关开启，其效果没有暴露。两个未完成任务的末尾仍在搜索容器或地点，提示搜索覆盖与12调用预算之间存在瓶颈；没有利用隐藏状态确认目标的真实位置，不能断言更长预算必然成功。

## 同四题对照

fixed 与 dynamic 使用相同题目、模型、任务文字、提示、子技能接口及动作上限；四个配对的首次规划 prompt 和 system prompt完全一致。fixed 消费非终止队尾，dynamic允许异常截断；历史增强和对象检查开关保持一致。

两组均2/4成功。双方共同成功的两题中，dynamic共9次调用，fixed共13次，但这些成功轨迹没有真实截断，不能归因于 interrupt。唯一发生真实截断的 dynamic 任务与对应 fixed 任务均达到调用上限。

两组分先后运行、每题每组只有一次；即使temperature=0，也保留供应商模型波动与顺序影响。不能从33对37调用、4对6非法动作宣布稳定改善。尚未完成 ReAct 或原版 SkillOpt 的公平优势验证。

## 下一步

当前优先分析失败任务的搜索覆盖与容器状态利用，而不是再扩写通用边界提示或开展全量 benchmark。先以公开轨迹标注已搜索地点、重复访问、目标首次可拿取时刻及剩余队列；保持任务文字和当前稳定接口，找出真实信息机会出现时是否有可丢弃队尾。
