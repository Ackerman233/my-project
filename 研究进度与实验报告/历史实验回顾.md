## 0. 先读结论

研究目标始终是：让 agent 使用可合并的动作片段减少决策次数，在偏差出现时及时中断并恢复；之后利用成功/失败轨迹进化技能，最终对照 ReAct 和原版 SkillOpt。

历史实验已经证明“代码能执行真实 chunk、能实际截断队列、能产生并筛选进化候选”。在一些简单 Sudoku 和个别 ALFWorld 成功任务上，也确实观察到合并动作减少模型调用。

**仍未证明：interrupt 提高整体成功率、进化收益能稳定迁移、或者本方法普遍超过 SkillOpt。** 原因不只是样本少，还包括基础解题/恢复能力不足、协议问题、接口中止、机制未触发和候选泛化退步。不能把所有负结果归结为“必须离线学习”。

本回顾根据既有报告和保存的结果整理，没有新增实验。表中阶段数字只在各自协议内解释，不把不同任务难度、模型、输出协议、预算上限或重试版本混成总成功率。旧报告中的“当前停止/工作区干净/预算余额”是当时快照，不代表今天。

## 1. 从搭工程到发现旧 chunk 不是真正 chunk

最初基于官方 SkillOpt 的 ALFWorld 基础设施搭建 `dynamic_skill/`、`experiments/`、`results/`，实现 ReAct、fixed、dynamic 等入口。

旧 ALFWorld 记录中，Qwen3.5 的 ReAct/fixed/dynamic 都有 2/2 成功，但对应总模型调用和环境步数分别为 13/13、28/28、14/14。也就是说旧 fixed/dynamic 仍逐步调用模型，不能作为真正动作合并的证据。

随后改为“一次模型输出动作数组 → 逐个环境执行 → 队列耗尽或异常后再规划”，并加入实际丢弃动作日志。最初真正队列版也遇到接口长时间等待、未完成 episode；脚本集成测试不补算模型成绩。

**这一阶段的纠正：模式名字不等于机制实现，必须核对实际调用与动作序列。**

证据：`outputs/rollout_comparison_20260928/FULL_RESULTS.md` 的“历史记录补充”。

## 2. Rush Hour / Sudoku 长程接入与超时（2026-09-27）

接入两类环境：Rush Hour 两题最短 20/25 次车辆移动；Sudoku 两题各 41 空格。求解器仅离线校验题目，运行时不向模型提供答案；数独 checker 只看局部合法性，不偷偷核对最终解。

最初 Qwen3.5 三模式共 12 个 episode，全部最终因接口错误中止。13 次请求中只有一次正常返回：生成 4 个动作并真实执行，随后超时。这次正常响应报告 8,294 reasoning tokens，说明当时没有可靠地关闭原生思考；不能把当时超时当作算法失败。

后来明确发送 `enable_thinking=false`，校准输出协议并修复 ReAct 提示中“只出一个动作”与“鼓励多个动作”的冲突。最终取用 12 个 episode：11 个达到某项预算上限，1 个超时，全部未完成任务。

| 环境 | 模式 | 两题总调用 | 非法动作 | 真实截断 |
| --- | --- | ---: | ---: | ---: |
| Rush Hour | 单动作 | 128 | 124 | 0 |
| Rush Hour | fixed | 36 | 90 | 0 |
| Rush Hour | dynamic | 18 | 18 | 15 |
| Sudoku | 单动作 | 128 | 110 | 0 |
| Sudoku | fixed | 51 | 110 | 0 |
| Sudoku | dynamic | 18 | 17 | 16 |

动态组确有 31 次真实中断、丢弃 65 个动作，但模型仍反复产生非法动作。较少调用主要来自更早终止，不能称作效率提升。

证据：`outputs/puzzle_pilot_20260927/实验说明.md`、`outputs/puzzle_nonthinking_report_20260927/实验结果.md`。最终 12 条记录是修复协议后选定的完整分组，不是全部校准尝试。

本轮 72 次 API 请求，4 次未知 usage 超时触发停止线；没有候选进入独立验证，默认 strict 保留。C02 的在线轨迹显示正确新棋盘和错误反馈已送入请求，模型仍重复非法动作；不能因此确定供应商路由或模型内部原因。

## 4. GPT-5.4 是否解决恢复问题（2026-09-28）

先在同样冻结状态与原提示上做探针，区分模型基础能力和控制器效果。

- GPT 在一个 Rush 初始状态输出 `A+4`，一步完成，优于该状态的旧 Qwen 输出。
- 但同题的两个恢复状态中，GPT 分别输出空数组、非法动作，均未成功恢复。
- 另一 Rush 初始状态，Qwen 一步完成，GPT 只取得部分进展。
- 两个单空格 Sudoku 探针 GPT 均完成；其中一个 Qwen 历史记录是接口错误，不能算能力失败。

六个不同提示最终均有正常通信响应，另保留一次历史连接错误。**不能得出“GPT 能恢复、Qwen 不能”。** 重试返回空数组是解析失败，不是连接失败；冻结状态探针也不是完整 episode 或长程恢复率。

证据：`outputs/gpt54_recovery_20260928/RESULTS.md`；原始记录分为 `online_attempt/diagnostic/`、`retry_1/`、`remaining_1/`，不得挑选最好答案混算。

## 14. 哪些结论应该保留，哪些应撤回

| 可保留的结论 | 不能升级成的结论 |
| --- | --- |
| 某些成功任务里 chunk 节省调用 | 所有长程任务都节省成本、提高成功率 |
| 有真实队尾丢弃、信息传给下一规划 | 模型一定能恢复，或者中断时机最优 |
| 一次验证集 gate 选中候选 | 候选已证明泛化优于初始技能 |
| 简短说明在一题上恢复成功 | 原生思考必须打开，或所有题都需推理链 |
| 代理后一轮无接口错误 | 旧错误必然由未开代理导致，代理永不超时 |
| Qwen请求发送 enable_thinking=false | 缺失 reasoning 字段就证明供应商内部零思考 |
| SPACE 提供训练边界监督的思路 | 不做离线学习就必然没有 gain |
| 动态组某次2/2而对照1/2 | 已经超过 SkillOpt，或已学出中断参数 |
